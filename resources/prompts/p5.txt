ここまでの分析結果と、転職者のプロファイルを突き合わせ、各条件の充足判定と総合所見を出してください。
点数化・おすすめ度の判定はしません（それらは後段のPHPが機械的に決めます）。

やること:
- プロファイルの「必須条件」を1つずつ取り出し、求人票・公式データ・口コミ（P2〜P4）に照らして充足を判定する
- 同様に「歓迎条件」も1つずつ判定する
- 判定は met（充足）/ unmet（明確に不充足）/ unknown（材料が無く判断できない）の3値
  ※ 材料が無い・触れられていない条件は unmet ではなく unknown にする
  ※ 断定できないもの（グレー）は unknown 寄りに倒す
- P2 の判定のうち verdict が "split" のものは、複数の判定者が別々の観点で検証して解釈が分かれた主張で、確証がない
  ※ verdict が "split" の主張だけを根拠に met と判定しない。他に裏付けが無ければ unknown に倒し、
     evidence に「判定者の間で判断が分かれている」と書く
  ※ 各判定者の判断と根拠は、その行の consensus.opinions に入っている
  ※ これは P2 の verdict の値であり、P4 の split_points（口コミで評価が割れた点）とは別物なので混同しない
- プロファイルの「NG条件（絶対に避けたい）」それぞれについて、材料から hit（該当の可能性あり）/ clear（該当しない）/ unknown（材料が無く判断できない）を判定する
  ※ 根拠1文を evidence に書く。断定を避け、材料がなければ unknown とする
  ※ verdict が "split" の主張だけを根拠に clear と判定しない（必須・歓迎条件と同じく unknown に倒す）

出力:
- must_checks: 必須条件ごとの配列。各要素 { condition: 条件そのもの, status: met|unmet|unknown, evidence: そう判定した根拠（P2〜P4の該当箇所を引く。無ければ「材料なし」） }
- want_checks: 歓迎条件ごとの配列。構造は must_checks と同じ
- ng_checks: NG条件ごとの配列。各要素 { condition: 条件そのもの, status: hit|clear|unknown, evidence: そう判定した根拠1文（無ければ「材料なし」） }
- appeal: この企業の一番の魅力（1文）
- concern: この企業の一番の懸念（1文）
- summary_lines: 総合所見3行の配列 [1行目=全体感を一言 / 2行目=一番の魅力 / 3行目=一番の懸念]

点数・おすすめ度・ランクは出力しない。断定語（「ブラック」「嘘」等）は使わない。
